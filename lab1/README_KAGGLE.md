# ЛР1: повторная серия на одной T4 в Kaggle

Предварительные опыты Colab не входят в итоговые таблицы Kaggle. Старые файлы и прогноз сохраняются отдельно. Все итоговые серии используют одну T4, одну ревизию Qwen3-4B-Instruct-2507, FP16, контекст 32768, vLLM 0.33.0 и TRITON_ATTN.

## Порядок

1. На ноутбуке `python lab1/prepare_kaggle_assets.py`: фиксирует ревизию модели и данные. Затем commit/push исходников, конфигурации, endpoint.yaml, данных и прогноза.
2. В Kaggle клонировать именно этот коммит; результаты размещать вне клона.
3. Создать `/tmp/lab1-env` с Python 3.13; установить vLLM 0.33.0, openai, mlflow, matplotlib. Сохранить pip freeze. Проверить CUDA и одну GPU. Команды приведены в сопровождающей инструкции.
4. Импортировать `kaggle_helpers` из lab1. `start_server(False)` — сервер без кеширования. `stage('check')`, затем `stage('exp1')`.
5. `checkpoint('exp1')` и скачать архив. `start_server(True)`, `stage('cache')`, `checkpoint('cache')`.
6. `start_server(False)`, `stage('exp2')`, `checkpoint('exp2')`, `stage('exp3')`, `checkpoint('exp3')`.
7. `stop_server()`, `stage('analyze')`, `checkpoint('final')`. Скачать ZIP и SHA-256; сохранить блокнот без запуска новой вычислительной сессии. Остановить сессию Kaggle после скачивания.

`stage` запускает отдельный процесс: `/tmp/lab1-env/bin/python lab1/kaggle_run.py --stage STAGE --root /kaggle/working/lab1_artifacts`.

## Условия и артефакты

- exp1: 5 длин входа × 5 повторов, ответ 16 токенов; префиксный кеш отключён.
- cache: отдельный прогрев другим текстом, затем 3 полностью одинаковых запроса на 8192 токена, ответ 16; кеш включён.
- exp2: вход 1024, ответы 16/64/256/1024, 5 повторов; кеш отключён.
- exp3: 1/2/4/8/16/32 клиента, max(16, 4c) запросов на уровень; вход 1024, ответ 128, разные участки книги; закрытый цикл клиентов. Прогрев каждого уровня отдельно. Снимки /metrics до, во время и после уровня, приблизительно раз в секунду.
- Все длины проверяются по серверному usage; несоответствие записывается как ошибка и останавливает серию. Автоматические HTTP-повторы отключены. Ошибки, прерванные и повторные серии не удаляются.
- Успешные запросы содержат исходные временные отметки и фрагменты. Ошибочные запросы сохраняют доступные частичные данные. Не все потоки дают ровно один токен в одном фрагменте: TPOT — оценка по временам первого/последнего фрагмента и серверному числу токенов.
- Условия: p90 TTFT <= 2 с и медиана TPOT <= 0,1 с. Goodput: число отдельных запросов с TTFT <= 2 с и TPOT <= 0,1 с / время уровня. Время уровня — от первой отправки до последнего текстового фрагмента.
- analyze пересчитывает метрики из файлов, выбирает последнюю завершённую серию каждого этапа, явно сохраняет её ID и проверяет одинаковые конфигурации, коммит и версии. Сравнивать разные повторные серии следует явно, без отбора по метрикам.
- Скорость prefill оценивается как input_tokens / median(TTFT); TTFT содержит и другие задержки. Fit второго опыта: T = a + b*(N-1), чтобы a сопоставлять с TTFT, b с TPOT.
- Очередь и заполнение кеша наблюдаются дискретно, короткие пики между снимками могут быть пропущены. Отсутствующие метрики обозначаются null, не нулём.
- Проверка 64 токенов и совпадение текстов при temperature=0 сохранены в check. Совпадение не гарантируется при других условиях. KV-размер вычисляется по config выбранной ревизии; сравнение с журналом необходимо проверить по сохранённым строкам. Для T4 примерная оценка чтения 4B FP16 весов: 8e9 / 300e9 ≈ 0,027 с, не точный предел конкретного запуска.

MLflow получает исходные результаты и графики после серий; это импорт из файлов, не повторное выполнение запросов. База и артефакты сохраняются в root. Для локального просмотра используйте `lab1/import_mlflow_local.py --root ПАПКА_РАСПАКОВАННОГО_АРХИВА`: создаётся новая локальная база и локальные URI артефактов; исходная база Kaggle не переписывается. Импорт повторно не добавляет уже зарегистрированные исходные ID.

## Важно для сдачи

Код подготовлен с ИИ-помощником. До реального выполнения нет заявленных GPU-результатов Kaggle. Подготовка отчёта Word/PDF на 3–4 страницы и проверка его оформления выполняются после получения файлов. Окружение и веса модели в Git и архив результатов не входят. Публичный endpoint не создаём, клиент и сервер работают на одной машине Kaggle. В следующих работах сервер запускается вновь из сохранённого паспорта и конфигурации.
