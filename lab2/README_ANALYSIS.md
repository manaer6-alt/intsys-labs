# ЛР2: анализ сохранённых результатов и локальный MLflow

Запускать из корня `intsys-labs` после копирования трёх файлов этой поставки в `lab2`.
Нужны исходные данные SciFact, предыдущие модули ЛР2 и уже установленное окружение.
Новые библиотеки устанавливать не требуется.

## Назначение

- `analyze.py` проверяет контрольные суммы архива, входов, ответов и эталона;
  сравнивает правила оценки с зафиксированными до эксперимента;
  пересчитывает качество, метрики поиска и попарные переходы «исправлено/испорчено»;
  сохраняет таблицы, три графика и четыре разбора случаев.
- `import_mlflow_local.py` переносит сохранённые облачные серии и общий анализ
  в эксперимент `lr2_scifact` локального MLflow.
- Этот файл описывает порядок запуска и ограничения интерпретации.

Обучение, поиск по BGE и генерация Qwen повторно не запускаются. Проверка бюджета
использует только уже скачанный токенизатор Qwen и сохранённую поисковую выдачу.
Уменьшение бюджета не даёт новых предсказаний: пересчитывается наличие обоснования.
Токенизация выполняется в коротком дочернем процессе, который завершается перед
построением графиков и импортом в MLflow. Дополнительных действий от пользователя нет.

## Основная метрика и отдельная диагностика

Правило `evaluation.py`, зафиксированное до вызовов модели, сохраняется:
ответ засчитывается, если вызов завершён, JSON и ссылки прошли проверку,
а метка совпала с эталоном. Ошибочные ответы остаются в знаменателе.

В серии oracle 26 ответов содержат допустимый JSON, но ссылаются на непереданные
номера предложений. В 24 из этих ответов множество номеров равно переданным
номерам минус один. Они не перенумеровываются и не отправляются на выборочный повтор.

`label_only_accuracy_diagnostic` считает совпадение одной метки на всех
запланированных примерах, включая ответы с неверными ссылками. Это дополнительная
диагностика; она не заменяет основную метрику и не вычисляется только на успешном подмножестве.

Oracle сравнивается с LLM-only и RAG k=3 дополнительно на одних и тех же
60 утверждениях SUPPORT/CONTRADICT (`common60.csv`). Остальные серии имеют 90 примеров.
Метрики поиска и эталонных ссылок считаются только на 60 примерах с обоснованиями.
NOINFO остаётся в общей точности и полноте своего класса.

## Запуск анализа в PowerShell

```powershell
& ".\.venv\Scripts\python.exe" ".\lab2\analyze.py" `
    --archive ".\lab2\lab2_final_2fb415a1.zip" `
    --budget-check 1024 --mlflow

if ($LASTEXITCODE -ne 0) { throw "Анализ ЛР2 завершился ошибкой" }
```

Рядом с архивом обязателен файл `lab2_final_2fb415a1.zip.sha256`.
Каждый анализ получает новую папку `runs/lab2_analysis/<analysis_id>`.
Путь к последнему успешному анализу сохраняется в `runs/lab2_analysis/latest.json`.

## Что получится

- `summary.json`: все показатели, знаменатели, попарные сравнения и диагностика oracle.
- `analysis_metadata.json`: хеш архива, версии программ, серверный профиль, коммиты.
- `tables/metrics.csv`: качество и время каждой серии.
- `tables/retrieval.csv`: Hit@k, Recall@k, MRR@k и наличие полного обоснования.
- `tables/common60.csv`: сравнение режимов на общем подмножестве oracle.
- `tables/paired.csv`, `pair_details.csv`: исправленные/испорченные ответы и ID.
- `tables/predictions.csv`: оценка каждого ответа без исключения неудач.
- `tables/oracle_diagnostics.csv`: переданные/возвращённые номера и ошибки проверки.
- `tables/budget_1024.csv`: пересборка RAG k=3 с меньшим бюджетом, без новых ответов.
- `figures/quality.png`, `retrieval.png`, `oracle_diagnostics.png`: готовые графики.
- `case_studies.md/json`: утверждение, найденные документы, переданный текст, сырой ответ и эталон.
- `forecast_original.md`: исходный прогноз без исправлений после эксперимента.
- `source/`: проверенная распакованная копия исходного архива.
- `mlflow_import.json`, `tables/mlflow_runs.csv`: соответствие исходных ID записям MLflow.

Категория «найдено, но полное обоснование не передано» может отсутствовать.
Программа сообщает её фактический состав; в четвёртом разборе тогда используется
ошибка номера в oracle. Случаи выбираются по минимальному подходящему ID.

`generation_s` измерено на клиенте от отправки HTTP до получения полного тела ответа.
Оно включает обработку сервера и обмен, но не поиск: поиск выполнен заранее локально
один раз на утверждение. Это не время изолированного вычисления GPU.

## Просмотр в MLflow

В отдельном терминале из корня проекта:

```powershell
& ".\.venv\Scripts\mlflow.exe" ui `
    --backend-store-uri "sqlite:///lab2/mlflow_local.db" `
    --host 127.0.0.1 --port 5002
```

Открыть в браузере `http://127.0.0.1:5002`, выбрать эксперимент `lr2_scifact`.
У пяти основных серий есть метрики качества; у `check` только проверки выполнения.
У `analysis` находятся общие таблицы, рисунки и разбор ошибок в разделе Artifacts.
Импорт регистрирует шесть облачных серий и отдельную запись анализа.

Если анализ получен, а импорт завершился ошибкой, анализ повторять не обязательно:

```powershell
$lab2Analysis = Get-Content -LiteralPath ".\runs\lab2_analysis\latest.json" -Raw -Encoding utf8 |
    ConvertFrom-Json
& ".\.venv\Scripts\python.exe" ".\lab2\import_mlflow_local.py" --analysis $lab2Analysis.path
```

Одинаковые исходные серии из одного архива повторно не создаются. Повторная
регистрация общего анализа получает новую запись.

Данные MLflow хранятся локально: `lab2/mlflow_local.db` и `lab2/mlartifacts/`.
Они, исходный ZIP и `runs/` не добавляются в Git. Для отчёта позже отдельно
копируются только нужные итоговые таблицы и рисунки.

Справка API MLflow: https://mlflow.org/docs/latest/api_reference/python_api/mlflow.html
